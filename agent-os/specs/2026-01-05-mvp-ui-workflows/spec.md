# Specification: MVP UI + Workflows

## Goal

Build a complete email client UI with three-pane layout, virtualized list, conversation reader, full-page composer, search, and core actions (archive, delete, star, read/unread, folders/labels) to deliver a keyboard-first, lightning-fast email experience.

## User Stories

- As a power user, I want to navigate through thousands of emails smoothly using a virtualized list so that I can quickly find and process messages without performance lag
- As a professional managing multiple accounts, I want to compose HTML emails with proper MIME formatting and attachments so that my messages are compatible with all major email clients

## Specific Requirements

**Three-Pane App Shell**

- Left pane contains sidebar with folders/accounts navigation using shadcn-vue sidebar-07 block pattern
- Center pane displays virtualized email list with TanStack Virtual for 60 FPS scrolling with 10,000+ items
- Right pane shows email reader/conversation view with HTML rendering and thread display
- Layout uses flexbox or CSS grid for responsive sizing between panes
- Sidebar is collapsible for more screen space when needed

**Virtualized Email List**

- Use existing VirtualList.vue component with TanStack Virtual already implemented in codebase
- Each list item displays sender name, subject, preview text (~100 chars), timestamp
- Visual indicators: unread dot, star icon, attachment icon (minimal design for performance)
- No inline labels/folder tags to maintain performance with large lists
- List items are clickable to open in reader pane and highlight selected state
- Support multi-select for batch operations (archive multiple, delete multiple)

**Conversation Reader**

- Display full email HTML content with sanitization (reuse mime_parser.rs sanitize_html logic)
- Show conversation threads with message history in chronological order
- Handle quoted replies and nested threading from references_header and in_reply_to fields
- Display attachments list with filename, size, mime_type, and download capability
- Reader toolbar contains action buttons: archive, delete, star/unstar, mark read/unread, move to folder, apply labels

**Full-Page Email Composer**

- Composer replaces entire main content area (not modal) for easier keyboard shortcut handling later
- Integrate Vue Tiptap WYSIWYG editor for HTML email composition
- Header inputs for To, Cc, Bcc (comma-separated email addresses), and Subject
- Rich text toolbar with bold, italic, underline, lists, links formatting options
- Drag-and-drop file attachment support with visual file list showing filename and size
- Auto-generate plain text fallback by stripping HTML tags from Tiptap output
- Send button calls send_email Tauri command with multipart/alternative MIME structure (reuse smtp.rs Email and EmailRecipients structs)

**MIME Message Formatting**

- Composer sends emails via existing send_email Tauri command in email_operations.rs
- Backend smtp.rs already handles multipart/alternative (plain text + HTML) structure using lettre crate
- Frontend provides body_html from Tiptap and body_plain (auto-generated by stripping HTML)
- Ensure HTML output from Tiptap is compatible with Gmail, Outlook, Apple Mail (avoid unsupported CSS, inline styles preferred)

**Basic Text Search**

- Search input in app shell queries search_messages Tauri command from search.rs
- Backend uses SQLite FTS5 for full-text search across sender, subject, body text
- Results displayed in email list pane filtered to matches only
- Highlight search terms in list preview text using snippet with `<mark>` tags from FTS5
- Search applies to current account or all accounts based on UI selection

**Core Email Actions**

- Archive: Move message to "Archive" folder (update messages.folder field in SQLite)
- Delete: Call delete_message Tauri command to remove from database
- Mark read/unread: Call mark_read/mark_unread commands to toggle is_read field
- Star/unstar: Call star_message/unstar_message commands to toggle is_starred field
- Actions accessible via toolbar buttons in reader pane and right-click context menu on list items
- Batch actions support for multi-selected messages (e.g., archive 10 emails at once)

**Folders and Labels System**

- Support traditional folders: messages.folder field (INBOX, Archive, Sent, Trash, custom folders)
- Support Gmail-style labels: create message_labels junction table (many-to-many relationship)
- Sidebar displays folder list (from folders table) and label list with message counts
- Move to folder UI: Dropdown or context menu to change messages.folder value
- Apply/remove labels UI: Multi-select dropdown or tag picker to modify message_labels entries
- Frontend syncs with SQLite folders table and new message_labels table

**UI Components from shadcn-vue**

- Sidebar navigation uses sidebar-07 block pattern from shadcn-vue
- Action buttons use existing Button.vue component
- Dialogs for folder/label management use existing Dialog.vue components
- Input fields use existing Input.vue component
- Cards for reader pane use existing Card.vue components

## Existing Code to Leverage

**VirtualList.vue Component**

- Reusable virtualized list with TanStack Virtual already implemented at src/components/VirtualList.vue
- Accepts items array, itemHeight, containerHeight, overscan props with slot for custom item rendering
- Exposes scrollToIndex and scrollToOffset methods for programmatic scrolling
- Use this component for email list pane with email data as items prop
- Reference VirtualListDemo.vue for implementation example with 10,000 items

**SMTP Email Sending (smtp.rs)**

- SmtpClient and Email structs handle SMTP sending with multipart/alternative MIME format
- build_message function creates proper plain text + HTML structure using lettre crate
- send_email command in email_operations.rs queues emails in outbox table with pending status
- Reuse EmailRecipients struct for To/Cc/Bcc and Email struct for subject, body_plain, body_html
- Frontend should call send_email Tauri command with SendEmailParams matching existing interface

**MIME Parser and HTML Sanitization (mime_parser.rs)**

- sanitize_html function removes script tags, event handlers, javascript: protocols for XSS prevention
- Use this function in frontend or backend to sanitize HTML before rendering in reader pane
- ParsedMessage struct contains body_plain, body_html, attachments for displaying email content
- Attachment struct has filename, size, mime_type, content, is_inline, content_id fields

**Search with FTS5 (search.rs)**

- search_messages Tauri command queries message_fts table using SQLite FTS5
- Returns MessageSearchResult with id, subject, from_addr, snippet (with `<mark>` tags for highlights)
- Frontend should call this command with query string and optional account_id filter
- Use snippet field to display preview text with highlighted search terms in list items

**Email Operations Commands (email_operations.rs)**

- Tauri commands for mark_read, mark_unread, star_message, unstar_message, delete_message already implemented
- All commands accept message_id or message_ids (for batch) and update SQLite messages table
- Frontend should invoke these via Tauri invoke API for action button clicks

**SQLite Database Schema (migrations/20260105000001_initial_schema.sql)**

- messages table has folder, is_read, is_starred, thread_id, body_plain, body_html fields
- accounts, threads, attachments, outbox, sync_state, folders tables already exist
- Indexes on account_id, date, thread_id, folder, is_read, is_starred for fast queries
- Need to create message_labels junction table for Gmail-style labels support

**shadcn-vue UI Components**

- Button, Card, Dialog, Input components already installed in src/components/ui/
- Use these for consistent UI styling following Tailwind CSS v4 and shadcn-vue design system
- Reference sidebar-07 block pattern from shadcn-vue website for sidebar navigation structure

## Out of Scope

- Customizable keyboard shortcuts configuration (deferred to roadmap item #8 and #15)
- Email sync engine and background syncing (separate roadmap item #2)
- Account management UI for adding/editing accounts (separate roadmap item #1)
- Snooze and Send Later features (roadmap items #12 and #13)
- Snippets and templates for reusable email responses (roadmap item #14)
- AI-powered features like compose assistance and thread summaries (roadmap items #17 and #18)
- Split Inbox rule-based views for Important/Notifications/Other (roadmap item #10)
- Command Palette (Cmd+K) for fuzzy search actions (roadmap item #9)
- Inline images in composer using base64 or cid attachments (only file attachments supported)
- Reply, Reply-All, Forward actions in composer (basic compose new only for this phase)
